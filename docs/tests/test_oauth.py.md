## Что проверяет

Обмен refresh-токена. Сети нет: `_post_refresh` подменяется, поэтому проверяется решение, а не
доступность Anthropic.

## Главный тест — `test_rotation_under_us_is_discarded`

Мок перед возвратом ответа переписывает файл кредов другим `refreshToken`, изображая claude,
который стартовал на этом слоте, пока висел наш POST. Ожидание: результат `skipped`, файл на диске
не тронут.

Это единственная защита от того, чтобы ccas установил токен, который сервер уже отозвал, — а цена
ошибки здесь ручной перелогин посреди работы.

## Остальное

`merge_tokens` не должна терять старый refresh-токен, когда ответ его не вернул (ротация
опциональна), и не должна выбрасывать незнакомые ключи вроде `subscriptionType`.

`test_busy_slots_are_derived_from_live_sessions` кладёт файл сессии на **настоящий** живой pid
(`subprocess.Popen` со `sleep`), как это делает `test_concurrency`: проверка на живость ходит в
`tasklist`/`os.kill`, и выдуманный номер её не пройдёт.

`test_failure_puts_the_slot_on_cooldown` вызывает обмен дважды и требует ровно один поход в сеть:
без кулдауна мёртвый аккаунт стоил бы round-trip на каждом листинге.
