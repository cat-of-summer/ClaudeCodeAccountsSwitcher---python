# daemon.py
<!-- DOCGEN:END -->

## Назначение

Процесс, который опрашивает бота и раздаёт строки чата сессиям. Один на токен — Telegram не даст двух, лок это отражает локально. Всё остальное следует из этого факта.

## Жизненный цикл

Автозапуск ОС выводится из профилей: `reconcile_autostart` заводит запись, когда есть профиль с `daemon: on`, и снимает её, когда таких не осталось. Отдельной настройки нет.

`ccas daemon run [--hidden]`: проверка конфига (нужен только токен), лок токена, локальный HTTP на 127.0.0.1 (порт в `daemon.json` и в локе), поллер, цикл с обновлением лока и чисткой маршрутов, обработка SIGINT/SIGTERM. `--hidden` прячет окно консоли на Windows (`ShowWindow(GetConsoleWindow(), 0)`) — так демона запускает автозапуск. `ensure_running` — ленивый старт из любого `ccas`/`claude`, если `telegram-daemon` включён, а демон не жив; при отсутствии frozen-бинарника запускается текущий интерпретатор с `main.py`.

## Маршруты

Транспорт регистрирует `Route(pid, tag, profile, chat, thread, cwd, slot)` и опрашивает `/poll?pid=…` long-poll-запросами. Маршрут без опроса 90 с или с мёртвым pid удаляется. Апдейт направляется так: кнопка — по метке (`tag`) в `callback_data`, `d:` — кнопки демона; текст — `routing.route` по профилям, потом проверка `allows`; `/claude` → запуск (до передачи в живой транспорт: для разговора это был бы просто текст); живой маршрут профиля → ему; `daemon: on` → запуск окна плюс очередь, которая сливается в маршрут при регистрации; иначе тишина, а на обращение по имени или слэш-команду — подсказка, как поднять профиль.

Слушаемых чатов по умолчанию нет: это решают профили.

## /claude

`/claude [слот] [-n имя] [-C каталог] [аргументы]` — те же аргументы, что у `claude` в терминале, и выполняется всегда: флаг `daemon` управляет только автоподъёмом по обычным сообщениям, а это явная просьба человека. Подкоманды и `-p`/`--version`/`--help` выполняются разово с захватом вывода. Иначе: имя валидируется по списку профилей, профиль должен быть открыт для этого чата, уже запущенный в этом чате профиль не поднимается вторично, каталог выбирается по цепочке `-C` → профиль → каталог чата → `telegram-workdir` → домашний (с учётом `roots`), слот — из аргументов или профиля, аргументы профиля идут перед аргументами из чата. Потом `open_window`: Windows — `CREATE_NEW_CONSOLE` (или без окна при `telegram-console off`), Linux — найденный эмулятор терминала, macOS — Terminal через osascript. В окружении спавна `CCAS_TELEGRAM_FEED=1`, `CCAS_TELEGRAM_TAG`, `CCAS_TELEGRAM_DAEMON_PORT`.

## Каталоги

Каталог чата хранится в `telegram/chats.json` по ключу `chat:thread`. `/projects` берёт `claudecfg.known_projects()` — реальные пути из `~/.claude.json: projects`, существующие, без дублей, новые первыми — и показывает их кнопками постранично.
