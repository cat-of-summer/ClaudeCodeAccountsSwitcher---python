# wrapper.py
<!-- DOCGEN:END -->

## Назначение

То, что выполняется, когда бинарник запущен под именем `claude`. Выбирает слот, направляет claude на его креды, запускает и записывает результат.

## Разбор аргументов

Правила строгие, выигрывает первое совпавшее:

| Аргумент | Действие |
|---|---|
| `--` | снять и **не** резолвить слот |
| `123` | номер слота, снять |
| `@alias` | слот по алиасу, снять |
| всё прочее | активный слот, аргументы не трогаем |

Алиасы требуют префикса `@` намеренно. Без него `claude work` съел бы однословный промпт вместо того, чтобы отправить его в claude. `claude -- 2` — аварийный выход, если промпт состоит из одних цифр.

Подкоманды claude (`mcp`, `update`, `doctor`, `agents`, `auth`, …) под эти правила не подпадают и проходят нетронутыми.

### Промпт в командной строке

Отдельного флага для промпта нет и не нужно: у самого claude он позиционный, а обёртка передаёт
всё, что не распознала как слот, как есть.

```
claude "Привет, сделай X"          # активный слот, сессия сразу берёт задачу
claude 3 "Привет, сделай X"        # то же на слоте 3
ccas run 3 "Привет, сделай X"      # то же из ccas
claude -p "Привет"                 # неинтерактивно: ответ в stdout и выход; автосмена выключена
```

Две острые грани, обе с одним обходом — `claude -- <промпт>`:

* однословный промпт из одних цифр читается как номер слота;
* однословный промпт, совпадающий с подкомандой claude (`update`, `doctor`, `mcp`), уходит в
  claude как подкоманда.

## Голый `claude`

Меню обёртка не показывает — меню живёт в `ccas`. Без аргументов `default_slot` берёт активный
слот, если у него есть креды, иначе тот из слотов с кредами, что использовался последним.
Скрипт, пайп, `claude -p ... | tee`, интеграция с IDE получают ровно то же самое.

## Аргументы по умолчанию

`merge_default_args` подмешивает `default_args` из конфига, но:

* пропускает флаг, если пользователь передал его сам;
* считает `--dangerously-skip-permissions` и `--allow-dangerously-skip-permissions` двумя написаниями одного и того же;
* не добавляет ничего к подкомандам — `claude mcp list` от такого флага только ругнётся.

## Два режима работы с кредами

### env — основной

Перед запуском в окружение дочернего процесса кладётся `CLAUDE_SECURESTORAGE_CONFIG_DIR=creds/<n>`. Копирования нет ни до, ни после: claude обновляет токены сразу в каталоге слота. Гонки параллельных терминалов не существует.

### copy — фолбэк

Порт логики `CC-Save` / `CC-Restore` / `CC-Clear` из PowerShell-профиля, плюс то, чего в нём не было:

* файл-лок с PID и предупреждение при запуске второго слота;
* **сохранение только если креды на диске всё ещё наши** — сверка по `accountUuid`. Без этой проверки терминал, закрывшийся вторым, затирал свежие токены соседа. Это была главная дыра исходного скрипта.

## После выхода

В блоке `finally` снимается identity и кеш лимитов. Любая ошибка бухгалтерии логируется, но не подменяет код возврата claude — пользователь должен видеть именно его.

## Шина хуков

Перед `Popen` обёртка поднимает `HookBus` (`core/hookbus.py`) и добавляет к аргументам
`--settings sessions/<pid>.settings.json` — файл, в котором все события claude направлены на
локальный порт шины. Свой `--settings` пользователя сливается в этот файл. Подкоманды, `--bare`
и `--safe-mode` шину не получают (`wants_hook_bus`). Супервизор может передать в `launch()` уже
открытую шину, чтобы она пережила перезапуск. При выключенном `artifactPublish` (по умолчанию)
`open_hook_bus` подписывает на шину `hookbus.block_artifact_publish` — публикация артефактов
отклоняется, файл остаётся локальным.

## Транспорт

`main()` мигрирует конфиг (демон поднимает транспорт именно через обёртку) и снимает флаги ccas (`-t/--transport`, `--tg-*`, `-C`, `-P`) через
`app/transport/routing.split_launch_options` и при `-t telegram` отдаёт запуск `app/transport.run`
вместо `run_slot`. Слот-бухгалтерия для обоих путей одна — `slot_session()`, контекст-менеджер,
внутри которого раньше жил `run_once`.

## Супервизия и автосмена

`run_slot` разделён надвое. `run_once` — это всё вышеописанное: подготовка слота, запуск, разбор
после выхода. `_supervise` крутит `run_once` в цикле, меняя слот между итерациями. Когда автосмена
выключена или сессию нельзя перезапускать (пайп, подкоманда, `--bg`), идём прямо в `run_once`, и
поведение ровно прежнее.

Бухгалтерия обязана исполняться на **каждой** итерации: `capture_identity` и `copy_mode_save`
пер-слотовые. Порядок «сначала разобрать старый слот, потом подготовить новый» держится сам собой —
`run_once` завершается целиком до следующего вызова, поэтому `capture_identity` читает общий
`~/.claude.json`, пока там ещё личность прежнего аккаунта.

### Почему решение принимает отдельный поток

claude при исчерпании квоты **не завершается** — он остаётся в приглашении и отказывается работать.
Ждать его выхода значило бы не сделать ничего полезного, а убивать заранее нельзя. Поэтому
`launch` отдаёт `Popen` через `on_started`, а поток `_reap` ждёт сигнала вотчера, проверяет квоту
по сети, выбирает цель и только после этого гасит процесс.

Побочно `Popen` починил старое: прежний `except KeyboardInterrupt: return 130` возвращал
управление, оставляя ребёнка работать с терминалом.

### Как гасится процесс

POSIX — `terminate()`, пять секунд, `kill()`. Windows — `taskkill /PID <pid> /T` без `/F`, пять
секунд, затем `/F /T`. `/T` обязателен: claude плодит node-детей, которые держат консоль, и
убийство одного родителя оставило бы терминал непригодным для сессии, которую мы тут же запускаем.

Потери минимальны: транскрипт пишется построчно, теряется незавершённый ход — тот самый, который и
получил 429.

### Консоль после убитого claude

claude (ink) переводит консоль в raw-режим, уходит в альтернативный экран `?1049`, включает
мышиный репортинг `?1000`/`?1006` и прячет курсор. Вышедший сам claude всё это откатывает; убитый
через `taskkill` — нет: обработчики выхода у него не запускаются. В таком окне Ctrl+C приходит
байтом `0x03`, а не сигналом, `input()` не показывает набранное, а следующее напечатанное ложится
поверх чужого экрана. Именно так выглядело «ccas: все аккаунты исчерпаны — жду…», после которого
процесс не убить ничем, кроме диспетчера, и «ccas открылся, но писать в него нельзя».

`launch` снимает состояние консоли (`system/console.snapshot`) до `Popen` и в `finally`
возвращает его (`restore`) и дописывает сброс экрана (`sanitize`). Оба вызова — на **главном**
потоке, после `wait()`: жнец гасит claude, пока главный поток ещё сидит в `wait()`, и
восстановление оттуда гонялось бы с ребёнком за консоль. Отдельно `main` обёртки и `cli.main`
первым делом делают `console.repair()` — чинят окно, которое испортил предыдущий запуск.

### Ожидание сброса

Когда свободного слота нет и `pick_target` назвал того, кто откроется раньше, claude уже погашен,
и терминал наш. `_wait_for_reset` ведёт обратный отсчёт в заголовке окна и опрашивает клавиатуру
напрямую (`console.poll_key`), а не полагается на `KeyboardInterrupt`: причина, по которой мы тут
оказались, могла оставить консоль в состоянии, где Ctrl+C — просто клавиша.

* Ctrl+C, Esc или `q` на пустой строке — не ждать; сессия завершается с кодом claude.
* Любой печатный символ начинает строку; Enter принимает её, Esc сбрасывает, Backspace правит.
  Принятая строка возвращается из `_wait_for_reset` и через `relaunch_args(resume_prompt=…)`
  становится первым промптом возобновлённой сессии вместо настроенного `resumePrompt`.
  Последняя принятая строка выигрывает.

Это замена родной очереди сообщений claude, которую наш `taskkill` отменяет — см.
[autoswitch.py](autoswitch.py.md), раздел про `quota_auto_resume`.

### Что обновляется перед выбором цели

`_refresh_candidates` запрашивает лимиты по сети для **всех** слотов, которые в принципе можно
ждать (`autoswitch.waitable`) — включая текущий и уже пробованные, за вычетом того, что вызывающий
только что получил сам. Раньше обновлялись только кандидаты на немедленный переход, а ветка
«кто откроется раньше» ранжировала текущий и пробованные слоты по снимкам, которых никто не
трогал с момента ухода с них.

### Числовые настройки

Читаются через `_number`, а не через `value or default`. «Не переключаться» (`maxSwitches: 0`) и
«без паузы» (`minIntervalSeconds: 0`) — законные значения, и `or` выбрасывает ровно их.
