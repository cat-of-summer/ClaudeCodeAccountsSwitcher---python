## Назначение

Режим менеджера — то, что выполняется, когда бинарник запущен под именем `ccas`.

## Первое, что делает `main`

`console.repair()` — до разбора аргументов и до миграций. Окно, в котором ccas только что убил
claude, остаётся в raw-режиме, и без этого меню рисовалось, а ввод в него не попадал; см.
[system/console.py](../system/console.py.md).

## Команды

| Команда | Что делает |
|---|---|
| `ccas install` | установка или накат новой версии |
| `ccas reinstall` | синоним `install` |
| `ccas uninstall [--purge]` | снять перехват; `--purge` удаляет и токены |
| `ccas list [--refresh]` | список аккаунтов |
| `ccas switch <цель>` | сменить активный слот |
| `ccas add` | подсказать свободный слот |
| `ccas remove <цель>` | удалить слот вместе с токенами |
| `ccas rename <цель> <алиас>` | задать алиас |
| `ccas usage [--cached]` | лимиты по аккаунтам |
| `ccas config [ключ [значение]]` | посмотреть и изменить настройки |
| `ccas doctor` | диагностика |

Голый `ccas` без подкоманды показывает список, а на неустановленной системе — справку.

## config

Голый `ccas config` в терминале открывает экран правки, в пайпе — просто печатает список. Так
`ccas config | grep` остаётся полезным, а человек не обязан помнить имена ключей.

Раньше единственным способом изменить `--dangerously-skip-permissions` было переустановиться, да и
то `install` при апгрейде молча наследовал прежний ответ. Теперь `reinstall` **спрашивает**,
подставляя текущее значение дефолтом (Enter ничего не меняет), а `install` поверх существующей
установки по-прежнему молчит — скриптовый апгрейд не должен вставать на промпте.

## Односимвольные команды в REPL

`r` — список с обновлением по сети, `l` — без, `s` — экран настроек. Через `_dispatch` то же самое
доступно как `list --refresh`, но за этим приглашением возвращаются именно чтобы обновить лимиты, и
набирать длинную форму по второму разу никто не станет.

## Разрешение цели

`_resolve_target` принимает номер, `@алиас`, голый алиас или префикс email. Неоднозначный префикс — ошибка со списком подошедших, а не молчаливый выбор первого.

Алиас не может быть числом: иначе он спутался бы с номером слота.

## doctor

Проверки идут в порядке причинно-следственной связи, чтобы первая же строка указывала на корень проблемы:

1. Версия установки против версии запущенного бинарника
2. Прописан ли каталог shim в PATH
3. Разрешается ли `claude` в наш shim **в текущем терминале**
4. Существует ли оригинальный claude и какой он версии
5. Режим кредов
6. Целостность каждого слота и права на файлах
7. Расхождение аккаунтов между конфигами claude

Пункт 3 — предупреждение, а не ошибка, если каталог в PATH прописан: правка PATH достаётся только тем шеллам, что запущены после неё, и сразу после установки промах здесь ожидаем.

Код возврата 1, если найдены настоящие проблемы; предупреждения на код возврата не влияют.
