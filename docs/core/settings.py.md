# settings.py
<!-- DOCGEN:END -->

## Назначение

Реестр настроек: один список `Setting`, из которого читают и `ccas config`, и интерактивный экран.

Смысл в том, чтобы добавление настройки было одной записью в таблице, а не правкой парсера,
принтера и экрана по отдельности. Ключ настройки задаёт и имена ключей каталога:
`config.label_<key>` и `config.help_<key>`. Тест на это есть — забытая русская строка ловится сразу.

## `skip-permissions` — вид, а не поле

В конфиге нет булева «пропускать подтверждения», есть список `defaultArgs`. Геттер проверяет
наличие `--dangerously-skip-permissions`, сеттер снимает или ставит его, **не трогая остальные
элементы списка**: кто дописал туда свой флаг руками, не должен потерять его от щелчка в меню.

## Разбор значений

`on/true/1/yes` и `off/false/0/no` плюс локализованные ответы из `common.yes_answers` —
`ccas config auto-switch да` работает наравне с `… on`.

Числа проверяются по диапазону из самой записи реестра, а не по месту использования; запись с
нулевыми границами (`telegram-chat`) принимает любое целое — id групп отрицательные и длинные.
Вид `dir` требует существующий каталог, `secret` маскирует значение в выводе (`telegram-token`
показывается как `123456:…6789`). Ошибки летят как `SettingError` с уже переведённым текстом:
слой команд его просто печатает.

`telegram-daemon` — единственная настройка с побочным действием: её сеттер регистрирует или
снимает автозапуск демона (`system/autostart.py`), чтобы включать было нечего по отдельности.

## Запись

`apply` всегда перечитывает `Config` с диска, меняет одно поле и сохраняет. Экран настроек живёт
долго, и держать в нём загруженный при открытии конфиг значило бы затирать правки, сделанные из
соседнего терминала.
