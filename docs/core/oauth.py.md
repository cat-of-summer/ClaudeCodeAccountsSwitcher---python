# oauth.py
<!-- DOCGEN:END -->

## Назначение

Обмен refresh-токена на свежий access-токен. Нужен ровно для одного: увидеть лимиты аккаунта,
которым сейчас не пользуются.

## Зачем это вообще

Access-токен живёт часы, refresh-токен — недели. У активного слота токен обновляет сам claude, а
у остальных он протухает через полдня простоя. `GET /api/oauth/usage` таким токеном отвечает 401,
поэтому до появления этого модуля лимиты чужих аккаунтов не обновлялись **никогда** — и выбирать
аккаунт «по лимитам» было не из чего.

## Запрос

Параметры сняты с установленного `claude.exe`, а не угаданы: тело идёт **JSON-ом**, не
form-urlencoded.

```
POST https://platform.claude.com/v1/oauth/token
Content-Type: application/json

{"grant_type":"refresh_token","refresh_token":"…","client_id":"9d1c250a-…","scope":"… …"}
```

`invalid_grant` и вообще 400/401 — токен мёртв, повторять бессмысленно. 5xx и таймаут — временно.
Разница видна в возвращаемом коде: `dead` против `failed`, и только `dead`/`failed` включают
пятиминутный кулдаун в `Slot.token`.

## Четыре защиты записи

Порядок в `refresh_slot` не случайный, каждая проверка закрывает свой сценарий:

| Защита | Что закрывает |
|---|---|
| слот в `busy` (из `sessions.busy_slots`) | на слоте работает claude и держит refresh-токен в памяти — ротация выкинет его из сессии |
| `file_lock` на `creds/<n>/.refresh.lock` **с проверкой флага** | два `ccas list` в двух терминалах |
| перечитать креды под локом + `needs_refresh` | сосед успел обновить, пока мы ждали лок |
| сверка `refreshToken` перед записью | claude обновил токен, пока висел наш POST |

Флаг `file_lock` проверять обязательно. По таймауту он отдаёт `False` и **разрешает писать без
лока** — для `accounts.json` это осознанный компромисс (потерянный апдейт дешевле незапустившегося
claude), для `.credentials.json` это потерянный refresh-токен и ручной перелогин.

Главная опасность — ротация refresh-токена — на практике мала именно потому, что модуль нужен для
простаивающих слотов: там нет живого процесса, у которого можно отобрать токен.

## copy-режим

В нём настоящие креды активного слота лежат в общем `~/.claude/.credentials.json`, а `creds/<n>/` —
устаревшая копия. Обновление копии либо будет затёрто на выходе, либо подсунуто поверх токена,
который claude уже сменил. Поэтому слот, названный в `sessions.read_lock()`, не трогается.

## Бекап

`_backup_credentials` не просто зовёт `backup_file`: копия дополнительно ужимается по правам.
`backups/` не хардится так, как `creds/`, а файл с токенами — единственное здесь, чему нельзя
расширять доступ по пути в бекап.
