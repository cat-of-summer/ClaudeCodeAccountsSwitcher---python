## Назначение

Две задачи: найти настоящий `claude` и выяснить, что он умеет.

## Поиск оригинала

Наш shim стоит в PATH **первым**, поэтому наивный `which claude` нашёл бы нас самих и получилась бы рекурсия. `find_real_claude` исключает каталог shim из перебора.

Порядок поиска:

1. PATH за вычетом каталога shim
2. `~/.local/bin` — место нативной установки
3. Глобальный bin из `npm prefix -g`

## Проба поддержки изоляции

`supports_securestorage` ищет в исполняемом файле байтовую строку `CLAUDE_SECURESTORAGE_CONFIG_DIR`.

Файл читается кусками по мегабайту с перекрытием в длину образца — совпадение на границе чанков не теряется, а нативная сборка на 264 МБ не загружается в память целиком.

Для npm-установки на PATH лежит лаунчер, а код — в `cli.js`. Если в самом лаунчере образца нет, `_js_targets` вытаскивает из него ссылки на `.js` и проверяет их.

## Кеш пробы

`probe_cred_mode` кеширует результат в `config.json` по ключу `(путь, размер, mtime)`. Обновление Claude Code меняет mtime и автоматически инвалидирует кеш — пересчёт произойдёт сам.

Результат — один из двух режимов:

| Режим | Поведение |
|---|---|
| `env` | `CLAUDE_SECURESTORAGE_CONFIG_DIR` на слот, копирования нет |
| `copy` | перенос файла кредов туда-обратно, как в PowerShell-профиле |
